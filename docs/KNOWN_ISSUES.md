## 1. 搬运保持（摩擦夹持）—— 当前最需观察的环节

### 现象

抓取判定本身稳定有效，失败集中在**抬升/搬运阶段物体滑脱**：

```
夹爪闭合: 手指位置=0.0215 阈值=0.006 => 夹住    # 指尖确实被物体挡住
抬升后手指位置 = 0.0032 (闭合时 0.0215) => 滑落  # 物体脱出，手指闭拢
```

另有两种失败模式：物体下滑把手指**楔开到全开位**（接触几何不稳定）；
前一次失败动作把物体碰偏，后续抓取**空夹**（级联效应）。

### 当前策略

| 阶段 | 力矩 | 目的 |
|---|---|---|
| 闭合（`close_effort`） | 16 N（阶梯加载） | 轻触建立接触，不撞偏物体 |
| 搬运保持（`hold_effort`） | 30 N | 抓取确认后切换，抵抗搬运滑落 |
| URDF 手指 effort 上限 | 40 N | 防止 `gz_ros2_control` 截断保持力矩 |

### 历史教训（旧链路标定得出，结论仍适用）

提升力矩/摩擦系数**不是线性改进**：把闭合力矩从 16 N 提到 30 N、摩擦 3.0 提到 5.0，
成功率反而下降——高力矩经阶梯加载后每步增量更大，指尖以过高速度撞击物体，接触建立成功率反而降低。
探针实验（`scripts/test_hold_path.sh`）已证伪"forward controller 长时运动丢指令"：
停止下发指令 3s 后关节力矩仍保持，**滑落是接触物理问题而非指令丢失**。

### 后续路径（若成功率仍不理想）

1. 复核夹取高度：指尖接触区是否包住物体质心附近（当前 `tcp_offset` 可调）；
2. 降搬运 jerk：`motion.velocity_scaling` / `accel_scaling` 继续下调；
3. 物体侧减重或缩小物理步长（代价是仿真更慢）；
4. 对圆柱等易滚动物体，评估更换抓取接触面或引入 V 型槽指尖垫。

## 2. 投放策略：单一投放点

当前所有物体抓取后投放至 `graspnet.drop_pose`（单一投放点）。
如需按类别分区放置，需**先恢复分类能力**（计划在点云层面迭代，不引入 YOLO），
再改为按类别选投放点。

## 3. 规划偶发不可行

**现象**：下降/放置段的直线插补与 OMPL 位姿规划偶发失败（MoveIt 错误码 -99999）。

**处理**：已内建降级路径——直线不可达时退化为位姿目标规划，抓取位姿仍不可达则退回预抓取点，
投放位姿不可达则在当前位置释放。属 OMPL 采样的偶发不可行，非系统性缺陷。
若频率升高，可增大 `planning_attempts` 或多候选位姿重试。

## 4. 环境约束（非缺陷，属平台/依赖限制）

- **venv numpy 与 MoveIt 系统 numpy 不可混用**：venv 的 numpy 1.26 已移除 `np.float`，
  全局注入 `PYTHONPATH` 会让 MoveIt 启动失败。故由 `sorting_bringup/venv_env.py`
  **按节点注入**（点云预处理 / GraspNet 推理）。
- **`ament_python` symlink 安装**：ext4 原生分区启用 `--symlink-install`，
  改 `src` 后重启节点即生效；若排查环境差异可用 `NO_SYMLINK_INSTALL=1` 关闭。

## 5. kill -9 泄漏 FastDDS 共享内存段（曾致 180s 假死）

**现象**：系统偶发"假死"——服务请求无任何响应，等待 180s 超时。

**根因**：反复 `kill -9` 强杀 ROS 进程不会释放 `/dev/shm/fastrtps_*` 共享内存段，
残留段导致新启动系统的 FastDDS 服务/话题投递不可靠。

**修复**：`scripts/cleanup_sim.sh` 统一清理仿真/ROS 进程**并删除残留 SHM 段**；
`acceptance_run.sh` / `demo_start.sh` 启动前自动调用。

## 6. 旧 EXIT trap 用 `pkill -f 'gz sim'` 匹配不到 Fortress 进程

Gazebo Sim (Fortress) 的实际进程名是 `ign gazebo` 而非 `gz sim`，旧收尾 trap 因此从未生效，
每次验收都泄漏一个僵尸仿真器，叠加上一条的 SHM 泄漏后环境逐步恶化。
现 trap 统一改为调用 `cleanup_sim.sh`。
